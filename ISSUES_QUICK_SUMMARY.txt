FLASK JIRA EXPORT STUDIO - QUICK ISSUE SUMMARY

ROOT CAUSE: Token Mismatch Due to Server Reload
When the Flask server restarts, a new ACTION_TOKEN is generated.
If the user has already loaded the login page, their token becomes invalid.
When they submit the form, they get a silent 403 error with no visible feedback.

================================================================================
CRITICAL ISSUES (Must Fix)
================================================================================

ISSUE #1: TOKEN GENERATION RACE CONDITION
  File: app.py, Line 34
  Severity: CRITICAL
  
  Problem:
    ACTION_TOKEN = secrets.token_urlsafe(32)
    
    This token is REGENERATED every time the server starts.
    If a user loads the login page, then the server restarts, their token is invalid.
    
  What Happens:
    1. User loads login page (token = "abc123...")
    2. Server restarts (new token = "def456...")
    3. User submits form with old "abc123..."
    4. Server rejects with 403 Forbidden
    5. User sees NO error message - "nothing happens"
  
  Fix: Implement token versioning or refresh mechanism


ISSUE #2: SILENT 403 RESPONSE FROM protect_actions() MIDDLEWARE
  File: app.py, Lines 156-161
  Severity: CRITICAL
  
  Problem:
    @app.before_request
    def protect_actions():
        if request.method == "POST" and not secrets.compare_digest(...):
            return jsonify(error="Refresh the app."), 403
    
    This middleware runs BEFORE the route handler.
    If token doesn't match, it returns 403 with error message.
    But the client-side code may not properly display this error.
  
  Evidence:
    - No "Refresh the app." message shown to user
    - Console logs show 403 response
    - Form appears to do nothing
  
  Fix: Improve error handling in login.js and return better error messages


ISSUE #3: INADEQUATE CLIENT-SIDE ERROR HANDLING
  File: static/login.js, Lines 39-50
  Severity: HIGH
  
  Problem:
    const response = await fetch('/api/connect', {...});
    const data = await response.json();  // ← Could fail silently
    
    if (!response.ok) {
      throw new Error(data.error || 'Connection failed');
    }
    
    If response.json() throws an error, exception handling may not catch it.
    If the response is HTML (error page), parsing fails.
    If data.error is undefined, generic message is shown.
  
  Fix: Add proper validation before accessing response.json()
       Check response content-type header
       Provide more detailed error messages

WHAT THE USER EXPERIENCES
================================================================================

Scenario 1: Normal Case (No Server Restart)
  1. Load login page
  2. Fill in credentials
  3. Click "Connect"
  4. See success message ✓
  → Works correctly

Scenario 2: Server Restarted (Common Case)
  1. Load login page (token = "abc123...")
  2. Flask development server reloads automatically
  3. New token generated = "def456..."
  4. Fill in credentials with old token
  5. Click "Connect"
  6. Response: 403 Forbidden with message "Refresh the app."
  7. User sees: Nothing happens, no error message
  → BROKEN - this is the reported issue

Scenario 3: Network Error
  1. Load login page
  2. Network drops
  3. Click "Connect"
  4. Fetch fails
  5. User sees: Generic "Connection failed" message
  → Works, but could be clearer
